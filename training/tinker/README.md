# Tinker sweep (Appendix C.3)

This folder trains large open models on difficult advice with
[Tinker](https://tinker-docs.thinkingmachines.ai) and evaluates them on the
agentic-misalignment eval. It asks whether the gap between the two teachers,
Claude Sonnet 5 and GPT-5.6 Terra, also appears in models much larger than
Qwen3-14B. Appendix C.3 reports five models: DeepSeek-V3.1, Qwen3.6-27B,
NVIDIA-Nemotron-3-Ultra-550B-A55B, Kimi-K2.6 and Qwen3.5-397B-A17B.
`families.py` registers all 15 instruct models Tinker can train.

For each model the pipeline runs two finetunes (one per teacher) and three
evals (base model, Sonnet 5 finetune, GPT-5.6 Terra finetune). Every model
trains on the same rows as the Qwen3-14B teacher grid, in its own identity and
its own chat format. Identity is text, written into the JSONL. Chat format is
tokens, applied at render time by `render.py` the same way in training and in
the eval.

## Setup

```bash
python3 -m venv .venv-tinker
.venv-tinker/bin/pip install -r training/tinker/requirements.txt
bash evaluation/agentic_misalignment/setup_vendor.sh
```

The venv holds both `tinker` and `inspect_ai`, because the eval samples through
the Tinker provider in `tinker_provider.py`. Put `TINKER_API_KEY` and
`OPENROUTER_API_KEY` (for the judge) in the repo-root `.env`. Run the commands
below from `training/tinker/`. Data, render samples and run state are written
under `data/tinker/` and `runs/`; both are gitignored and regenerated by the
scripts.

The input data is the difficult-advice data in `data/difficult_advice/`
(download it from the HF dataset `SecondLookResearch/teaching-qwen-why-data`):
`sonnet-5-first/` (165 train rows, 229 val rows) and `gpt-5.6-terra-first/`
(135 train rows, 15 val rows).

## Pipeline

1. `recover_rungs.py` recovers the vendor-neutral rows behind the Qwen-adapted
   training files, so other families do not learn to call themselves Qwen.
   It writes `data/tinker/neutral/`. Run it once.
2. `adapt_dataset.py` writes each family's identity (assistant and developer
   name) into the rows: `data/tinker/adapted/<family>/`.
3. `check_render.py` is the gate before any training. For each model it
   renders a real training row and fails unless the family's settings produce
   a thinking-off prompt, the loss mask covers exactly the assistant turn, and
   `extract_response` returns the assistant content and nothing else. It
   writes a readable dump per model to `data/tinker/render-samples/`.
4. `train_sft.py` trains a LoRA adapter: rank 64 (32 where Tinker caps it),
   cosine schedule with 3% warmup, the cookbook learning rate (extrapolated
   where the cookbook has none), 4 epochs, batch size 8. It saves a sampler
   checkpoint after each epoch and selects the one with the lowest val loss.
   The dry run (the default) renders the data and prints the config, token
   counts and a cost estimate; `--yes` trains.
5. The eval stages call `evaluation/agentic_misalignment/msm_eval_run.py`
   with `--model tinker/<id>`. The model samples through the Tinker API, so
   there is no server and no `--base-url`. Each model is addressed by its own
   assistant name (`--model-name`, from `families.py`).

`run_model.py` runs all of this for one model and keeps resume state in
`runs/<slug>/state.json`:

```bash
../../.venv-tinker/bin/python recover_rungs.py
../../.venv-tinker/bin/python run_model.py --model deepseek-ai/DeepSeek-V3.1          # dry run
../../.venv-tinker/bin/python run_model.py --model deepseek-ai/DeepSeek-V3.1 --yes    # execute
```

Stages: `adapt`, `check_render`, `train-sonnet-5`, `train-gpt-5.6-terra`,
`eval-base`, `eval-sonnet-5`, `eval-gpt-5.6-terra`. A finished stage is
skipped on re-run, and `--redo <stage>` forces one. A finetune that failed
after saving paid checkpoints stops the driver, so you can choose to keep them
or retrain. Redoing a finetune moves its old eval log aside, because
`eval_set` would otherwise skip the conditions it already completed.

## Eval settings

The sweep uses the 6-condition subset (3 scenarios, `america` goal and no goal
conflict) with 30 samples per condition, 180 samples per model. Run names
follow the eval convention:

```
DeepSeek-V3.1__as-deepseek__6x30
DeepSeek-V3.1-difficult-advice-sonnet-5__as-deepseek__6x30
DeepSeek-V3.1-difficult-advice-gpt-5.6-terra__as-deepseek__6x30
```

For a verbose model whose samples truncate at 4096 tokens, pass
`--eval-max-tokens 8192` to `run_model.py`. A truncated sample grades as not
misaligned, so all three runs then use the larger cap and carry `-mt8192` in
their names. Kimi-K2.6 and Qwen3.5-397B-A17B were run this way.

Thinking is off in training and in the eval wherever the chat template allows
it. gpt-oss and Inkling have no off switch, only a reasoning-effort floor, and
their logs record `tcw_thinking: minimal`. `--no-thinking` and
`--stop-token-ids` do not apply to Tinker models and are refused.

Summarize the three runs of a model with:

```bash
cd ../../evaluation/agentic_misalignment
../../.venv-tinker/bin/python summarize.py \
  DeepSeek-V3.1__as-deepseek__6x30 \
  DeepSeek-V3.1-difficult-advice-sonnet-5__as-deepseek__6x30 \
  DeepSeek-V3.1-difficult-advice-gpt-5.6-terra__as-deepseek__6x30
```

The driver prints this command when all stages finish. The three runs share
one model id (the checkpoint travels as a model argument), so the run
directory name is what keeps them apart.
